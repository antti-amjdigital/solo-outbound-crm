Behaviour notes. Type chips filter rather than group — click Call and only calls remain, which is the batching move for a calling hour. Chips and time tabs combine (Overdue + Call). Overdue rows stay in the main list rather than hiding in their own tab, because a buried overdue call is a lost prospect. Completed rows stay in place struck through, so the list visibly empties as you work. Clicking anywhere in a row opens the prospect; Snooze ▾ gives +1 day / +3 days / next Monday / pick a date.

On dropping the step column: the subject already carries the position — “Call attempt 2” tells you where you are without a second column competing for the eye. Full sequence progress lives on the prospect page, where you actually need it.
Log call — production view. The full dialog, as it actually appears: opened over the queue, one conditional section matching the selected outcome, and a live preview of what the sequence engine will do when you save. Most dials never open this — they get logged with a single keypress from the row popover. This is for the ones that need a date or a real note.

What makes this production rather than wireframe. Only the conditional section for the selected outcome renders — Callback here, so a date picker with sensible quick options. Choose Meeting booked and this becomes a date-and-time field; choose No answer and it disappears entirely, leaving the dialog two fields tall.

The coloured dot on each outcome is the detail worth building. It tells you what the button will do to the sequence before you press it: grey advances, amber reschedules the current step, green and red end it. The engine's behaviour is otherwise completely invisible, and "why did this prospect stop getting called?" is the question you'd otherwise be answering with a database client.

The On save strip spells out the consequence in full sentences, with the real dates. It costs one line of code per outcome branch and removes an entire category of "wait, what did that just do?". The duration timer starts when the dialog opens, so talk time is captured without you doing anything.

What's borrowed, and what's ours. Three ideas carry over because they're structurally right: a pinned next-action so "what do I do about this person" is never below the fold, a type-filtered history rather than one undifferentiated stream, and notes attached to the event that produced them.

The execution is this app's own. No dashed gutter rail, no floating cards, no yellow bands — the history is hairline rows inside a panel, using the same square type icons and filter chips as the Today screen, so the two pages read as one product. Notes sit in an indented block with a plum rule; the date column is right-aligned rather than buried in a meta line, which makes the stream scannable by when as well as what.

Two things Pipedrive can't have: the Sequence panel on the left, and the “Before you dial” summary inside Focus — last outcome, dials remaining, and the pinned constraint, assembled into the one sentence you actually need at the moment you pick up the phone.

Focus holds exactly one entry, which falls out of the "only materialize the next task" rule from the spec. If it ever shows two for a single prospect, the engine has a bug.
Sequence editor — production view. Because only the next task is ever materialized, edits here need no migration: they apply to each prospect's next generated step. The dated preview prevents delay-day mistakes, the per-step numbers tell you which steps are worth keeping, and the impact banner prevents surprises.

Clarity fixes in this pass.

The save bar is now always on screen. It was sticky, but the page grew taller than the viewport so it sat below the fold — which is the same as not existing. The editor is now its own scroll container, so the bar pins to the bottom of the view no matter how many steps you add, and it's accent-tinted so it reads as a live action bar rather than a footer.

Column headers. The single cheapest fix for "what is this control?". Wait before — after previous step and Content — script or template answer both questions before you have to click anything. A one-line explainer above the list says steps run top to bottom and what the wait is measured from.

"Immediately" became "Start / no wait". Under a column headed Wait before, the first step's value has to read as "there isn't one" — not as a timing instruction you might have misconfigured.

Template buttons now carry state. Filled with an up-chevron means open, tinted with a tick means one exists, dashed + Add script means empty. Previously every step showed the same button whether or not it had content, so the only way to find out was to click all five.

Still the feature that earns the page its keep: per-step numbers. Attempt 3 has booked 3 meetings against attempt 1's 4, so it pays for itself. If it read 61 done · 1 connect · 0 booked, you'd delete the row and get the time back. Without these you're editing on instinct, because the funnel report lives on a screen you'd have to remember to open.
Prospects — production view. The database view: filter, select, bulk-enroll. CSV import and bulk enroll are day-one features, not nice-to-haves — hand-entering prospects isn't a workflow. The enroll dialog carries a spread over N days option, because bulk-enrolling 200 people otherwise dumps 200 tasks into today.

What changed, and why. The selection bar was dark navy, which made a transient state look like permanent chrome — dark is now reserved for the nav rail alone, and selection reads as an accent-tinted band instead. Selected rows are also tinted, so the bar's count and the rows it refers to are visibly linked.

Square checkboxes for selection, round ticks for activity completion. Two different meanings should never share a shape.

Applied filters carry the accent, idle ones stay quiet, with a live match count and a "Clear 2 filters" affordance. On a 418-row table, "why am I only seeing 63?" is the most common confusion, and this answers it without a click.

Next task became an icon plus a relative date rather than "Call · today", so the type is scannable at a glance and overdue reads red. Titles sit under names, companies truncate rather than wrap, and the table ends in a real footer with counts and paging — an infinite unlabelled list is where you lose track of how much list is left.
Stats. Every number comes from the immutable Activity log, never from tasks. The formula tooltip isn't decoration — in six months you won't remember what counted as a “connect”, and a metric you can't define is a metric you can't trust.

Charts over boxes, but only where a chart says something a number can't. The funnel is a funnel because drop-off is a shape. The heatmap exists to catch absence: a week you didn't prospect never shows up as a bad rate, only as a gap.
